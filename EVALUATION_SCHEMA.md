# ORP v2.0 - Evaluation Schema

## System Version
ORP v2.0 (Unified System Architecture)

---

## Purpose

This document defines the strict structural data transformation pipeline used across:

- PROMPT.md
- BENCHMARK.md
- RUBRIC.md
- SCORING.md

It defines how information moves through the system.

It does NOT define evaluation quality or scoring criteria.

---

# Core Principle

Each layer transforms data without reinterpretation beyond its defined role.

No layer is allowed to redefine meaning generated by another layer.

---

# 1. INPUT INGESTION

## Function
Capture raw input.

## Rules
- Preserve all claims exactly as provided
- No interpretation allowed
- No normalization or correction

---

# 2. CLAIM ATOMIZATION

## Function
Convert input into atomic units.

## Output Units
- factual claims
- inferred claims
- speculative claims
- structural relationships (explicitly stated only)

## Rules
- Each claim must be independent
- No merging of claims
- No inference of missing claims

---

# 3. EPISTEMIC TAGGING

## Function
Assign epistemic labels to each atomic claim.

## Allowed Labels
- Verified
- Unverified
- Speculative
- Disputed
- Invalid

## Rules
- Exactly one label per claim
- No hybrid labeling
- No probabilistic labeling
- No confidence scoring

---

# 4. RELATIONSHIP ANALYSIS

## Function
Identify explicit logical relationships between claims.

## Allowed Relationship Types
- causal link (explicit only)
- dependency link (explicit only)
- contradiction
- independence

## Detected Distortions
- causal inversion
- importance distortion
- false synthesis
- recency bias override

## Rules
- Do NOT infer hidden relationships
- Do NOT introduce external knowledge
- Only analyze explicitly present structure

---

# 5. INTEGRITY FILTER

## Function
Enforce epistemic separation rules.

## Constraints
- No merging of epistemic categories
- No upgrading of uncertainty to certainty
- No narrative reconstruction
- No assumption bridging

## Enforcement Rules
- Hallucinated anchors must be isolated
- Invalid claims must remain non-causal
- No cross-category blending allowed

---

# 6. OUTPUT RECONSTRUCTION

## Function
Rebuild structured interpretation.

## Allowed Inputs
- Verified claims
- Explicitly labeled uncertainty only

## Rules
- No new information generation
- No extrapolation beyond verified claims
- Unverified claims must remain isolated and non-causal
- Reconstruction must preserve uncertainty boundaries

---

# SYSTEM INTERFACE CONTRACTS

## PROMPT.md → Schema Input Contract
- Produces atomic epistemic structure input

## BENCHMARK.md → Stress Input Contract
- Produces adversarial or distorted claim sets

## RUBRIC.md → Evaluation Output Contract
- Consumes schema output for qualitative scoring

## SCORING.md → Numeric Aggregation Contract
- Consumes RUBRIC output only (not raw schema)

---

# CRITICAL SYSTEM RULES

- No layer may reinterpret another layer’s output
- No semantic drift between stages
- No backward influence (downstream → upstream forbidden)
- No assumption propagation between layers

---

# DESIGN PRINCIPLE

The schema defines structure transformation only.

Meaning is preserved, not reinterpreted.

Evaluation occurs downstream exclusively.
